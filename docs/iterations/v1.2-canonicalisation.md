# Version 1.2 — Canonicalisation

Status: complete  
Source: §6.2

Scope: mirror x, swap anatomical labels, separate recording and live camera metadata.

Tests: mirror twice restores original; x and labels both transform.

Gate: synthetic coordinates match expected canonical output.

## Result

- `canonicalise` applies both operations §6.2 requires. Negating x alone would leave a left knee at
  the right knee's position, so the label permutation is applied in the same pass.
- World landmarks mirror as `x = -x` (metric, hip-centred). Image landmarks mirror as `x = 1 - x`
  because they are normalised to [0, 1]; they are carried for drawing only and never used for
  geometry.
- `visibility` and `presence` are permuted alongside the coordinates. They are per-landmark
  channels, so leaving them unpermuted would attach the left leg's confidence to the right leg.
- `RecordingCameraMetadata` and `LiveCameraMetadata` are separate types, not one shared type with a
  flag. §6.2 warns that reading the manifest's `mirrored` as a runtime setting mirrors the patient's
  feed to match the physio's, which is backwards. Distinct types make that mistake a compile error
  rather than a silent one.
- Added `PoseLandmark` with all 33 MediaPipe indices and a `LATERAL_PAIRS` table. The mirror
  permutation is now built from named pairs instead of raw integer literals.
- Hardened the invariant the correctness of everything downstream rests on: tests assert
  `MIRRORED_INDEX` is a bijection over 33 entries and its own inverse, and that nose is the single
  unpaired landmark. A typo in the pair table previously could have produced a non-involution that
  the round-trip test alone would not necessarily catch.
- Gate: `gradlew.bat testDebugUnitTest --no-daemon --rerun-tasks` passed; 17 tests, 0 failures
  (6 in `CanonicalisationTest`).
- Verified `core` sources still import no Android APIs. No phone test required.
