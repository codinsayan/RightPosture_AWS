## NPU investigation — 2026-09-05, on the target device

Measured on an **iQOO I2501 (SM8850, Snapdragon 8 Elite Gen 5, Hexagon HTP v81)**, Android 16.

**Measured result: `Lite/GPU · 29 fps`.** The device gate's bar is ≥25 fps and the CameraX analysis
stream supplies 30, so the pipeline is within one frame of the ceiling the camera imposes. There is
no frame-rate headroom for an NPU to recover — the delegate is not what is limiting throughput.

The delegate ladder is now **NPU → GPU → CPU** (`PoseLandmarkerSource.initialise`), each rung falling
through to the next on failure. NPU is only attempted when the QNN dispatch library is present in
the APK, so the common case costs nothing and does not throw on every cold start.

### Why NPU does not currently engage, established by inspection rather than assumption

| Finding | Evidence |
|---|---|
| MediaPipe 1.0.0 **does** expose an NPU delegate | `javap` on `tasks-core-1.0.0.aar`: `Delegate.NPU` exists alongside `CPU`/`GPU` |
| It requires **two** native library directories, both mandatory | `BaseOptions.DelegateOptions.NpuOptions` has non-optional `dispatchLibraryDirectory()` and `compilerPluginLibraryDirectory()` |
| MediaPipe ships neither | no `.so` files in `tasks-vision-1.0.0.aar` |
| The device has QNN HTP libraries | `/vendor/lib64/hw/libQnnHtp.so`, `libQnnHtpV81Skel.so`, `libQnnHtpV81Stub.so` |
| …but an app **cannot load them** | absent from `/vendor/etc/public.libraries.txt`, so the app linker namespace refuses the `dlopen` |

Engaging the NPU therefore requires bundling the Qualcomm AI Engine Direct (QNN) dispatch and
compiler-plugin binaries into `jniLibs` per ABI — a licensed SDK download, not a Gradle dependency —
and very likely a quantised/NPU-compiled pose model rather than the stock float `.task` bundle.

**Deferred, deliberately.** The ladder is in place, so adding those binaries is the only remaining
step; no code change waits behind them. The argument for doing it is §10/§11.1's — keeping the GPU
free for the overlay and leaving NPU headroom for the on-device LLM — plus power and thermal
headroom over a long session. It is **not** a frame-rate argument, and the measurement above is why
that distinction now has a number attached to it.

- Device gate on frame rate: **passed** (29 fps ≥ 25 fps target, GPU delegate, iQOO I2501).
- Device gate remaining: skeleton alignment and front/rear behaviour with a person in frame.
