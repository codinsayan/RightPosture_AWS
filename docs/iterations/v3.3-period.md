# Version 3.3 — Dominant feature and period

Status: complete  
Source: §6.7.1–6.7.2

Scope: percentile swing ranking and normalised autocorrelation.

Tests: known periodic signal finds feature and period; aperiodic signal uses documented fallback.

Gate: first qualifying local maximum behavior passes.

## Result

- Added `core/reference/DominantPeriod.kt`: `selectCoarseDominantFeature` (§6.7.1) and
  `estimatePeriod` (§6.7.2), returning `PeriodEstimate(lagSamples, seconds, correlation)`.
- Swing ranking uses 5th/95th percentiles, not min/max, so a single spurious frame cannot win the
  ranking. A test contaminates a flat signal with one 1000-unit spike and asserts it still loses.
- Autocorrelation is normalised **per lag**, not by `r[0]`. §6.7.2 is specific about this: dividing
  by `r[0]` leaves a triangular bias that makes short lags spuriously dominant.
- The estimator returns the **first** local maximum with `r ≥ 0.4`, not the global one. §6.7.2 warns
  the global maximum can land on 2T and halve the rep count. Tested directly with a signal whose
  reps alternate in shape, so that `r[2T] > r[T]` and a global search would demonstrably return the
  wrong answer.
- Only the coarse first pass of §6.7.1 is implemented. The second pass recomputes swing over clean
  segments to confirm or switch the choice, and needs the segmentation from 3.4. The function name
  says `Coarse` so the caller cannot mistake one for the other.

### Two findings

1. **The 0.5 s lower bound does not reject movement faster than 0.5 s per rep.** A signal with a
   0.167 s period also correlates perfectly at every multiple, and lag 0.5 s is the first multiple
   inside the search window — so the estimator confidently reports 0.5 s, a rep count wrong by a
   factor of three. §6.7.2's bounds limit what the search can *see*; they are not a plausibility
   screen. This is now asserted as the actual behaviour rather than left to be discovered later, and
   catching it is the 3.8 validator's job. Movement slower than the 8 s upper bound *is* rejected,
   because no local maximum exists inside the window at all.
2. **Swings are compared across features with different units.** Fourteen features are degrees;
   `shoulder_elevation` is a dimensionless ratio ×100. §6.7.1 says to compare raw swing and does not
   address this, so no normalisation was invented. Noted in source. The plan's own argument is that
   the principal joint clears the others by an order of magnitude, which holds for the demo
   exercises but is not guaranteed in general.

### Changed from the draft

- Non-finite input now returns null instead of throwing. §6.22 treats NaN/Inf as invalid, not as a
  crash, and one bad sample in a recording must not take the authoring pipeline down. Same for a
  non-positive or non-finite sample rate.
- `selectCoarseDominantFeature` skips non-finite signals rather than propagating them.
