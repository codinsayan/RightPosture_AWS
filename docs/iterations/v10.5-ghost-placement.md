# Version 10.5 — Ghost placement and the sign-check screen

Status: complete — device gate passed by eye, 2026-09-30 (see the end of Result).  
Source: §6.16's lesson; new work

Scope: project a reference pose into image space over a live body, and a physio-facing sign-check
screen that draws it over **the physio's own recording**. No patient sees a ghost in this iteration.

Place it by fitting a 2D similarity — rotation, uniform scale, translation — that carries the
reference's hip-to-shoulder vector onto the patient's own, both measured in image space. The fit
needs only the four torso landmarks, so it survives a `REUSED` body frame; what does not survive
`INVALID` is phase, and `ExerciseEngine` already abstains there.

Tests: a body standing in the reference's own start pose has the ghost land on its own landmarks; an
oblique view draws nothing; a missing torso landmark draws nothing.

Device gate: **hard, and everything downstream waits on it.** Record a reference, replay it, and
confirm the ghost overlays the physio's own skeleton — front camera and rear camera, sagittal and
frontal, four combinations. A human looks at the screen and says yes.

## Result

Core (Track A):

- `core/live/GhostPlacement.kt` — `placeGhost(pose, frame, imageAspect, liveView, requiredView)`
  → `PlacedGhost?` of `GhostPoint`s in MediaPipe's normalised image coordinates. Projects on the
  live view's plane (frontal x/−y, sagittal z/−y), fits the similarity as one complex division, and
  returns null for: no/oblique live view, live view ≠ required view, a torso landmark below
  `VIS_MIN`, a side-on body with no nose, a degenerate torso, or facing below the margin.
- `core/reference/SkeletonReference.kt` — `poseAtPhase(phase)` (interpolated, clamped) and
  `replayPhases(segmentation, trace)` (each authoring frame's phase by the reference's own
  `phaseProfile`; a boundary frame shared by two reps takes the later rep's 0).
- `core/Params.kt` — `GHOST_FACING_MARGIN` 0.05 torso lengths, uncalibrated.

Front of the seam (Track B, logged in `CHANGELOG.md`):

- `camera/GhostCheckScreen.kt` — replays the recording in memory with the physio's skeleton (green)
  and the ghost (white); "Matches" / "Doesn't match" writes `RPGhost sign-check verdict=… camera=…
  view=… placed=n/N aspect=…`.
- `camera/Letterbox.kt` — `letterboxOf`, now used by **both** `SkeletonOverlay` and the ghost, so
  they cannot disagree about where the image sits.
- `authoring/ReferenceReview.kt` — optional `onCheckGhost`, shown only when a skeleton exists.
- `camera/CameraPreviewScreen.kt` — remembers the analysed image's aspect while recording (a
  `CapturedFrame` does not keep it) and routes to the check screen.

**Two things this does that the spec did not say.**

1. **The fit runs in aspect-corrected units.** MediaPipe's x and y are fractions of different
   lengths; a similarity fitted in them directly is a stretch on any non-square image. The reverted
   first attempt did exactly that. Tested at 3:4, 9:16 and 16:9.
2. **The geometric facing check moved here from 10.6.** This iteration's own test — the ghost lands
   on the physio's own landmarks — cannot pass without it: the similarity has no reflection, and on
   a rear camera the labelled-right shoulder is on screen-left, so an assumed axis direction mirrors
   the ghost half the time. Facing is measured across each body's own torso axis, in its own torso
   lengths, and the reference's horizontal axis is negated when the two disagree. 10.6 keeps the
   *anatomy* half (label swap between cameras) and the mirror-sensitivity tests.

`GhostPlacementTest` — 16 cases: lands on its own landmarks (frontal; mirrored camera; 9:16 and
16:9; 20° tilted camera; sagittal facing either way and mirrored); right way up; follows position
and size; draws nothing for oblique, unclassified, wrong view, each hidden torso landmark, side-on
without a nose, undecidable facing; body z never moves a frontal point; replay phases cover every
rep frame monotonically; `poseAtPhase` interpolates and clamps. Fixtures use an isotropic camera,
per the trap below.

Commands: `gradlew testDebugUnitTest assembleDebug` — BUILD SUCCESSFUL; 846 tests, 0 failures.

Device gate: **passed, 2026-09-30, by eye.** The user recorded on the phone, opened "Check the
ghost against this recording", and reported the ghost moving on their own skeleton ("it is matching
as I've seen"). That is the gate as written: a human looks at the screen and says yes.

What the record does **not** have: the per-attempt `RPGhost sign-check verdict=…` lines. They were
written on the phone and lost before `devicelog.py stop` read them — the phone's 256 KiB log buffer
is overwritten by ColorOS within minutes (the tool now streams to disk; see `CHANGELOG-core.md`).
So which of the four camera × view combinations were tried is not recorded. The rear camera in
particular is re-exercised by 10.6's cross-camera gate, which runs on the same screen with the log
now working.

## Why this iteration exists at all

The fit is exactly determined: four degrees of freedom, four equations. It **always** succeeds, and
always with zero residual, so it can never report that it is wrong. There is no error term to
threshold and no test that can be written against its own output.

§6.16's correction arrow has been dead code since 5.3 for precisely this reason — built, unit
tested, and never switched on, because nobody could demonstrate its signs were right. The sign-check
screen is how this one avoids the same fate, and it is why it ships before the ghost is ever put in
front of a patient.

## Traps

- **Negate y before fitting.** Body-frame y runs up the torso; image y runs down the screen. Leave
  them disagreeing and the fit resolves it as a 180° rotation — which also flips the horizontal axis
  and silently mirrors the entire ghost. It will look almost right.
- **Choose the projection plane from the patient's live view classification, not
  `manifest.requiredView`.** That label is a two-valued output of `classifyView`'s ratio thresholds;
  a recording 20° off sagittal still reads "sagittal". Use `requiredView` only as the gate that says
  "you are not in the view this exercise needs, so nothing is drawn."
- **Never let world z drive a drawn coordinate in a frontal view.** It is a learned depth prior, not
  a measurement. Occlusion ordering only.
- **Reuse `SkeletonOverlay`'s letterbox arithmetic exactly.** If the two ever diverge the ghost is
  correct on a 4:3 device and offset on everything else, which is the hardest kind of report to act
  on.
- **A frontal projection cannot see a movement made in the sagittal plane.** This is correct, and it
  is why `requiredView` gates the ghost at all. Pin it with a test so a later change has to be
  deliberate about it rather than discovering it as a mystery.
- **Synthetic fixtures will not catch a placement bug on their own.**
  `syntheticTwoStepRepetitions` maps world to image as `(0.5 + x, 0.3 − 0.5y)` — x and y scaled
  differently. That is a shear, no similarity transform can reproduce it, and no real camera has
  one. Rebuild the image landmarks isotropically from the same world pose in the test fixture, or
  every placement assertion is measuring the generator rather than the code.
