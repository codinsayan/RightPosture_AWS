# Version 8.7 — Richer summary context

Status: complete  
Source: §10.7, §6.18.5, §10.1, §1.6

Scope: feed the summary model the fatigue deltas §6.18.5 already defines, plus how many reps did not
count and why, without widening what the model may claim.

Tests: a delta we computed is allowed and one we did not is rejected; the word "percent" is refused
when no delta was computed; the template stays inside its sentence and word bounds.

Gate: no fabricated measurement, no new medical advice, and no legitimate number rejected.

---

## Why

The summary currently gets five facts: exercise name, reps completed and prescribed, median quality,
the change point, and up to two joint changes reduced to their **direction only**.

Three quantities §6.18.5 defines are computed nowhere and stated never, though every column they need
has been on disk since 7.1:

    ΔROM   = (mean ROM_post / mean ROM_pre − 1) × 100
    ΔTempo = (mean T_post / mean T_pre − 1) × 100
    ΔSmooth = SPARC_post − SPARC_pre

§6.18.5 calls rising roughness with falling ROM and slowing tempo "the textbook fatigue pattern;
naming it explicitly is what a physiotherapist will recognise instantly". Right now nothing names it.

`changesAfterOnset` also computes each joint's shift magnitude and discards it (`SessionFacts.kt:82`),
keeping only the sign — which is why §10.7's own worked example, "14% less range", is not currently
achievable by this pipeline.

## The five edits, and the sixth that is easy to miss

Adding a fact to `SummaryFacts` requires coordinated edits **or the validator rejects our own
legitimate output**, silently, by falling back to the template.

New fields, all `Int?` or enum and **never `Double`**, all defaulted so every existing construction
site and test compiles untouched:

    val repsNotCounted: Int = 0,
    val topRejection: String? = null,          // words only, no numeral
    val romChangePercent: Int? = null,         // sign kept
    val tempoChangePercent: Int? = null,       // sign kept
    val smoothness: SmoothnessShift? = null,   // direction only

1. **`SummaryFacts.kt`** — the fields. Deltas are null whenever `degradationOnsetRep` is null: a delta
   with no change point to be relative to is a measurement nobody took, and this is what lets the
   template safely say "after that point".
2. **`allowedNumbers()`** — guarded on non-null, and wrapped in `abs`. `NUMBER_RUN` is
   `\d+(?:\.\d+)?`, which never captures a leading minus, so whitelisting `"-12"` admits nothing while
   still rejecting the true sentence "12 percent smaller". For ΔROM −12, ΔTempo +8 and 2 uncounted
   reps the tokens are exactly `"12"`, `"8"`, `"2"`. No scale constant is needed here, unlike
   `QUALITY_SCALE`: a percent is a word, not a denominator.
3. **`summaryPrompt()`** — emit only when non-null, spelling `percent`, never `%`. The direction words
   (smaller/larger, slower/faster) are ours, derived from the sign, which is §10.1's guarantee made
   concrete: a bad paraphrase can be clumsy, never backwards. Also enrich the joint lines with the
   recovered magnitude **as a word** — `abs(shiftZ) >= 1.0` gives "drifted clearly further", otherwise
   "slightly" — so nothing new enters `allowedNumbers()`.
4. **`summaryTemplate()`** — exactly **one** new sentence, gated on `romChangePercent != null`. The
   maximal template today is 4 sentences and about 46 words, against bounds of 5 and 90; this makes it
   5 and about 55. That single sentence of headroom is precisely why ΔTempo, ΔSmooth and
   `repsNotCounted` stay prompt-only.
5. **`report/SessionFacts.kt summaryFactsOf()`** — populate from `setDeltasOf(...)` and
   `reps.filter { !it.valid }`. It already receives `reps`, so no new parameter and no call-site change.

### 6. The unit word

Verified at `SummaryValidator.kt:52` and `:86-91`. `SPELLED_MAGNITUDES` contains `"percent"`, and
rule 2 rejects any unit that does not already appear in `facts.changes.joinToString { it.description }`:

    if (unit in lower && unit !in factsText) reasons += "States a measurement we did not compute"

So a model correctly writing "12 percent smaller" **is rejected even with `"12"` whitelisted**.
Whitelisting the number is not enough. Add `allowedMagnitudeWords()` returning `setOf("percent")` when
either delta is present, and widen the guard to consult it.

Nothing else in `SPELLED_MAGNITUDES` becomes reachable — `degrees`, `sigma` and `standard deviation`
stay refused, which is correct: ΔROM is a ratio, and the model is never handed a degree measurement or
a raw z-score.

**Without this edit the feature fails silently.** Every delta-bearing summary is rejected twice, falls
to the template, and the only visible symptom is the attribution line reading "Summary from
measurements only" instead of "Written on this phone by Gemma". Two tests pin it.

## Why every number stays an integer

`checkSummary` counts sentences by splitting on `[.!?]+` (`SummaryValidator.kt:112`). A decimal such
as `1.8` therefore reads as a **sentence boundary**, inflating the count toward the 5-sentence
rejection — and a `1.8` token is also not admitted by whitelisting `"1"` and `"8"` separately, since
`NUMBER_RUN` matches it whole.

So `ΔSmooth` is reported as a **direction only, with no number**: `medianOf(sparcPost) −
medianOf(sparcPre)`, with `> +0.2` smoother and `< −0.2` less smooth. SPARC is negative and more
negative means less smooth, so that sign convention gets its own test rather than a comment.

## `setDeltasOf` — the arithmetic

In `report/Deltas.kt` (new, pure). Returns all-nulls when `onsetRep == null`. Splits on
`repIndex < onsetRep` versus `>=`, over **valid reps only**.

Restricting to valid reps is not tidiness. A `RANGE` rejection has a small `romDegrees` *by
definition*, so including rejected reps in the post window would manufacture a range collapse out of
the rejection criterion itself — a fabricated finding that would read as fatigue.

ΔROM is null if either side is empty or `meanPre < 1e-6`, and suppressed below
`MIN_REPORTABLE_PERCENT = 5` so noise never reaches the prompt.

## Word-list hazard in `topRejection`

The rejection phrasing goes into the prompt, the model echoes it, and the validator sees it. `"skip"`
is in `UNSAFE_ADVICE_WORDS`; `"strain"` and `"damage"` are in `DIAGNOSIS_WORDS`; `"therapy"` and
`"treatment"` are in `TREATMENT_WORDS`. 8.6 fixes the wording; a test iterating `RepRejection.entries`
through `checkSummary` keeps it fixed.

## Tests

`SummarySafetyTest.kt`, with a `maximalFacts` fixture carrying every new field:

- the template stays inside its bounds with every fact present — at most 5 sentences, at most 90 words
- the template passes its own validator, re-asserted on `maximalFacts`
- "12 percent smaller" is accepted and "13 percent smaller" is rejected
- the word "percent" is rejected when `romChangePercent` is null
- every numeral in an accepted summary is one `allowedNumbers()` permits
- the prompt carries the deltas

`SessionFactsTest.kt`:

- deltas are null when there is no change point
- the range delta uses only valid reps — a `RANGE`-rejected low-ROM rep after the onset must not
  manufacture a collapse
- every emitted delta token is an integer
- smoothness direction follows the SPARC sign

## Result

Built as planned, including the sixth edit. 717 tests, up from 701.

`report/Deltas.kt` computes the three §6.18.5 quantities; `SummaryFacts` gained five defaulted fields,
so no existing construction site moved. `SmoothnessDirection` lives in `core/summary` rather than
`report`, because `core` must not depend on `report` and both sides needed the type.

### The sixth edit was necessary, and a test proves it

`the word percent is refused when no delta was computed` fails against the old validator and passes
against the new one. Without `allowedMagnitudeWords`, a model writing "12 percent smaller" was
rejected **even with 12 whitelisted** - the unit is checked separately from the digit - and every
delta-bearing summary fell back to the template with no symptom beyond an attribution line reading
"Summary from measurements only".

Only `percent` becomes reachable, and only when a percentage was computed. `degrees`, `sigma` and
`standard deviation` stay refused, which is right: ΔROM is a ratio, and the model is never handed a
raw angle or a z-score.

`abs` before whitelisting also earned a test. `NUMBER_RUN` matches digit runs, so it never captures a
leading minus: whitelisting `"-12"` would admit nothing at all while still refusing the true sentence
"12 percent smaller".

### Valid reps only

`the range delta uses only reps that counted` is the test worth keeping. A `RANGE`-rejected rep has a
small `romDegrees` *by definition* - that is the rejection criterion, not an observation - so
including it would manufacture a range collapse out of the criterion itself and report it as fatigue.

### Budget

The template runs to 5 sentences and roughly 55 words with every fact present, against bounds of 5
and 90. That is why only ΔROM got a template sentence: it spends the last of the headroom. ΔTempo,
ΔSmooth and the uncounted-rep count stay prompt-only, where the model can fold them into 3-4
sentences that a fixed template cannot.

### Outstanding

Not yet measured on device. More facts in a prompt whose word budget did not grow may raise the
template-fallback rate, and the only way to know is a phone. `MIN_REPORTABLE_PERCENT = 5` suppresses
noise-level deltas so most sets will not carry them at all.
