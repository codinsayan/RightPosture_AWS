## Five screens, not §14's fourteen

§7.2 says to defer the decorative screens. Most of §14's table cannot be built *honestly* yet, which
is a stronger reason than decorative:

| §14 screen | Why not now |
|---|---|
| Patient list, Assign | Needs 7.4's invite linking. A list that can only ever be empty is worse than no list. |
| Progression curves | Needs 8.4, and a baseline nothing captures. |
| Demo | Needs a `demo.mp4` that nothing records yet. |
| Cue review | Needs 8.1/8.2 to generate cues, and faults are empty for all four exercises. |

Built instead: **role picker → physio home → authoring**, and **role picker → today → exercise**,
plus a session report. That is §7.2's gate — both roles reach their core flow — and nothing beyond
it.

## Hand-rolled navigation, not Navigation Compose

§7.2's gate is "navigation state tests and a back-stack smoke test". A plain immutable stack is
testable in the JVM suite the other 543 tests run in; Navigation Compose would push exactly those
tests onto an instrumented device, which is a worse place to discover the back stack is wrong.

`NavState` is an immutable `List<Screen>` — immutable because it crosses into composition, the same
reason `FrameResult` is.

Three behaviours that needed deciding rather than defaulting:

- **`back()` returns null at the root** rather than an empty stack. Null is the signal to let the
  system handle the press. An empty stack would leave nothing to render, and swallowing the press
  would trap the user on the home screen.
- **Navigating to the screen already on top is a no-op.** Without it a double tap pushes a
  duplicate, and the next back press looks broken because it pops to an identical screen.
- **Finishing a set uses `popTo`, not `navigateTo`.** A patient doing five exercises in a row would
  otherwise need five back presses to leave.

**Changing role resets the stack.** A physio's authoring screen has no meaning in a patient's
history, and leaving it below would let a back press cross between roles.

## What this makes real

7.1 wrote `.rpose` bundles to disk and recorded their paths, and nothing read them back. The patient
path now does: Today lists the `exercises` rows, tapping one reads the bundle off disk and opens
straight into §6.20 calibration. That is the first time the stored bundle is load-bearing rather
than merely written.

`CameraPreviewRoute` gained an optional `startBundle`. Null is the physio path and starts at
authoring; a bundle is the patient path and skips it. The screen was not split apart — that refactor
is real and still wanted (`PARALLEL-TRACKS.md` flags it), but doing it in the same change as
navigation would have made a regression impossible to attribute.

Two failure paths are handled rather than assumed away:

- **The `.rpose` file is missing** though its row survives — reinstall, cleared storage, a
  half-written bundle. The patient is told to ask for a re-record, rather than being dropped into a
  camera that can never score anything.
- **Process death restored the stack but not the in-memory bundle.** The exercise screen returns to
  Today instead of dereferencing null in front of a patient.

## Honest naming

"Today" lists the references on the device, not what a physio prescribed for today, because without
7.4 there are no assignments. The screen is named for what it becomes; its empty state says what it
currently is.

## Tests

`NavigationTest`, 10 cases: both roles reach their home; a stack is never empty; back pops one entry;
back at the root asks the app to exit; a duplicate push is ignored; a role change clears the other
role's history; five sets in a row leave the stack at one entry; `popTo` an unvisited screen resets;
two session reports are distinct destinations; and `(id, version)` makes two versions of one exercise
distinct, per §9.6.

`./gradlew testDebugUnitTest` — 553 tests, all pass. `assembleDebug` builds and installs.

## Outstanding

- **The device gate is unrun.** Both roles reaching their flow has been proven in tests and the
  build installs, but it has not been driven by hand on the phone — the device was locked at the
  time. Needs: launch, pick each role, confirm the physio reaches authoring and the patient reaches
  a set, and that back behaves at each step.
- **`CameraPreviewScreen` is still one composable** holding authoring, calibration, the cyclic set
  and the hold flow, now ~910 lines. Splitting it per flow is the next structural job and is worth
  doing before more screens are added on top.
- **Role is per-device, not per-account.** 7.3 replaces `RoleStore` with the signed-in account's
  role. Until then "switch role" clears the stored choice, which is honest for a demo where one
  person holds one phone.
- **The session report is a list, not §14.1's chart.** The quality curve, change-point marker and
  cue-effectiveness table are 8.3's, and the cue table additionally needs faults 8.1 has not defined.
