## Result

  `WatchedFeature`.
- Added `WATCH_LIST_MIN_ROM_DEGREES = 8.0` and `WATCH_LIST_MIN_VISIBILITY = 0.7` to `Params.kt`.
- **P3-15, the test §6.10 requires by name, is implemented under that name.** `ROM = 60°, σ = 22°`
  is asserted absent; `ROM = 40°, σ = 3°` is asserted present. The first case clears filters 1 and 4
  on its own, so filter 2 is the only thing that can reject it — which is exactly why the plan asks
  for it. An inverted filter fails here immediately rather than surfacing hours later as
  inexplicable scoring behaviour.
- All four filters written as **pass** conditions, matching §6.10's own rewritten table. Each has
  its own test at the boundary: 7.9° vs 8.0° ROM, σ 4° kept vs 18° rejected, visibility 0.69 vs
  0.70, salience 1.99 vs 2.00.
- Filter 2 reuses `Params.SIGMA_CAP_DEGREES` rather than declaring its own threshold. §6.9.4 warns
  that if the cap moves and the watch-list threshold does not, the two silently disagree; sharing
  the constant makes that impossible, and a test pins the behaviour at exactly the cap.
- Rejections are returned with the reason that caused them, ready for the 3.8 review screen, rather
  than features silently vanishing.
- The dominant feature is added **after** filtering, so it survives rejection. §6.8.2 derives phase
  from it, so a reference that does not score it is not scoring anything coherent. It is still
  reported in `rejected` when it failed, so the physio sees why.
- Weights are `salience / Σ salience` over the watch list, so the joints the physio controlled most
  tightly carry the most weight — the desired clinical behaviour, obtained for free. A degenerate
  reference with no usable salience shares weight equally rather than emitting NaN.

### Correction to v3.6

3.6 recorded `reachedCap` (σ reached the 15° cap in **any** bin) and documented it as feeding
filter 2. That was wrong on two counts: filter 2 tests the **median** over bins, not "any", and it
must read the **pre-clamp** σ. Because §6.9.4 clamps σ at 15° before inflating, a post-clamp median
can never exceed the threshold it is compared against, and §6.10's own required test case of σ = 22°
would not even be representable.

`FeatureReference.reachedCap` is replaced by `FeatureReference.medianSigmaRaw`. Both the v3.6 doc
and its changelog entry are corrected rather than left standing.

`salienceOf` reads the same pre-clamp value, for the same reason: measuring salience off the stored
band would compress the ranking at the top and scale every value by `k_inflate`.
