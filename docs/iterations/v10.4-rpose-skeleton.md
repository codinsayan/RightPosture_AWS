# Version 10.4 — skeleton.json at format 1.2

Status: in-progress — implemented and unit tested; device gate not yet run. **Shipped at format
1.1, not 1.2** — see Result.  
Source: §9

Scope: carry 10.2's poses and 10.3's time axis in the bundle as a new optional entry. Mirror the
`hold.json` precedent exactly — it is the established optional-entry pattern in this file.

Optional in both directions. Absent from every bundle written before 1.2, and absent from a 1.2
bundle whose recording could not support one. Its absence means the exercise is scored but not
demonstrated, never that the bundle is malformed.

Tests: round trip; a 1.1 bundle with no entry still reads and yields a null skeleton; a truncated or
mis-strided array is refused on load with a message naming the file; the entry stays small enough to
parse on a phone.

Device gate: author on device, reinstall the app, reopen the exercise — the ghost reference survives
the trip through storage and through Supabase (`ExerciseSync` treats the `.rpose` as opaque bytes, so
no sync change should be needed; confirm that).

## Result

- `core/rpose/Rpose.kt` — `RPOSE_SKELETON = "skeleton.json"`; `RposeBundle.skeleton` last and
  defaulted, not checked in `init`; written by `entries()` after `hold.json`; `skeletonJson` writes
  flat arrays rounded to four decimals with the stride documented beside it; `parseSkeleton`
  refuses, naming the file, a wrong landmark set, a grid other than 101 bins, any mis-sized array,
  a non-finite number, a non-boolean `fresh`, and — via `PhaseTiming`'s own checks — a backwards
  profile or non-positive duration. `REQUIRED_ENTRIES` untouched.
- `core/reference/BundleAssembly.kt` — `bundleFromAuthoring` passes `result.skeleton` through.
  `bundleFromHold` leaves it null.
- `sync/` — unchanged, and confirmed needing no change: nothing outside `core/rpose` and the three
  `readRpose` call sites parses a bundle; `ExerciseSync` moves bytes.
- `SkeletonBundleTest` — 14 cases: six entries in order; round trip to four decimals; a second
  trip exact; entry under 120 KB; no entry → null skeleton, reference intact; a 1.0 bundle still
  reads; the five older entries byte-identical with or without the skeleton; seven refusals, each
  asserting the message names `skeleton.json`.

**Deviation from this spec: no format bump.** The spec said 1.2, following `hold.json`. That bump
existed because a 1.0 reader would have parsed a hold bundle as an empty cyclic exercise and failed
in front of a patient. Nothing like that happens here: `parseRpose` reads named entries and ignores
the rest, so a reader without this code scores the exercise exactly as before and simply has no
ghost. A bump would have done the opposite of its purpose — every build without 10.4 (the other
track's included, pulling from Supabase) would refuse every newly authored exercise. The test
`adding the skeleton changes nothing an older reader looks at` pins it: format still 1.1, and the
other five entries byte-identical with and without the skeleton.

Commands: `gradlew testDebugUnitTest assembleDebug` — BUILD SUCCESSFUL; 830 tests, 0 failures.

Device gate: **not yet run.** Author an exercise on the phone, force-stop and reopen the app, and
open it from the Library: the `RPGhost` line is written at authoring, so the gate needs 10.5's
screen (or a debugger) to show the reloaded skeleton. Until then, the in-app check is that the
exercise still opens and scores, i.e. the new entry did not break the bundle.

## Traps

- **Flat arrays with a documented stride, quantised to four decimals.** `Json.kt` has no
  nested-array reader, and it writes every number through `Double.toString()` — a widened Float
  costs about seventeen characters. Written nested and unrounded this entry heads for a few hundred
  kilobytes of text and tens of thousands of boxed `Double`s on every exercise open. In torso
  lengths the fourth decimal is around a twentieth of a millimetre on an adult, far below anything
  MediaPipe resolves.
- **`RposeBundle` is constructed positionally in `parseRpose`.** A new field must go last or every
  argument after it is silently rebound.
- **Do not add a `require` to `RposeBundle.init`.** It fires for every in-memory construction,
  including all existing test fixtures. Shape validation belongs in the parse helper, where it can
  name the file — same as `parseHold`.
- **Leave `REQUIRED_ENTRIES` untouched.** That list is the whole mechanism for "optional".
- `RposeTest` asserts the exact ordered list of five zip entry names. It passes while that fixture's
  skeleton stays null; authoring fixtures will now produce six.
- Validate the time axis on load too, not just at build time — a non-monotonic profile would run the
  movement backwards mid-rep, and the file is the last place to catch it.
