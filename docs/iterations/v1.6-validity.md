# Version 1.6 — Validity and abstention

Status: complete  
Source: §6.6, §8.2, §6.22

Scope: confidence, vector, body-frame, recovery, and downstream validity contracts.

Tests: invalid data cannot score or cue; weights renormalise; invalid rep remains unscored.

Gate: every invalid path abstains.

## Result

- Added `core/pose/FeatureValidity.kt`: `validFeatures` (rules 1–4), `ValidityTracker` (recovery
  hold and occlusion timers), `renormaliseWeights`, `repIsScorable`, `FeatureKind`, and the
  `contributingLandmarks` table.
- All four §6.6 rules implemented. Rule 1 is `visibility ≥ 0.6` **and** `presence ≥ 0.6` on every
  contributing landmark; rule 2 is a 1e-3 m floor on every contributing vector; rule 3 checks
  finiteness and the declared range; rule 4 rejects the frame outright when the body frame is
  `INVALID` while accepting `REUSED`.
- Validity is layered on top of `extractFeatures` rather than duplicated inside it. Two parallel
  validity systems would drift apart, and §6.6 is a stricter filter over the same output rather
  than a different computation.
- The 1e-3 m floor is deliberately separate from the 1e-6 floor in `Angles.kt`. §6.22's 1e-6 is a
  numerical-safety guard against dividing by zero; §6.6's 1e-3 is a physical-plausibility bar — a
  1 mm shank is a detection failure, not a short limb. A test pins a value that clears the first
  and fails the second.
- Recovery hold implemented as §6.6 requires: a feature returning to validity is withheld until it
  has been continuously valid for 300 ms. A test simulates a landmark flickering on a 250 ms cycle
  and asserts it never emits once — the spurious-fault stream §6.6 warns about.
- `contributingLandmarks` returns landmarks in chain order so consecutive pairs are exactly the
  vectors rule 2 has to measure. This makes rule 2 fall out of the same table rather than needing
  a second hand-maintained list of vectors.
- Downstream contracts built as pure functions, not as part of a scorer that does not exist yet:
  `renormaliseWeights` returns an empty map when nothing is valid, so the caller must treat it as
  "no score this frame" rather than a score of zero. `repIsScorable` implements the >30% rule.
- §8.2 timers included since they are the same clock: `shouldWarn` at 500 ms for the "I can't see
  your left leg" message, `shouldGoIdle` at 1.5 s for a patient who has left frame.
- Gate: `gradlew.bat testDebugUnitTest --no-daemon --rerun-tasks` passed; 81 tests, 0 failures
  (20 in `FeatureValidityTest`).
- `core` still imports no Android APIs. No phone test required.
