# Version 5.2 — Google TTS and haptics

Status: in-progress - engine and en-IN data confirmed on device; first spoken cue still
blocked on 8.1 fault definitions  
Source: §12.4–12.5

## Scope

Use Android `TextToSpeech` with Google's installed engine package,
`com.google.android.tts`. This iteration does not use Google Cloud TTS, a network API, another
TTS engine, or a new SDK.

- Declare the TTS service query required for Android 11 and newer.
- Construct `TextToSpeech` with `com.google.android.tts` explicitly.
- Set `Locale("en", "IN")` only after successful initialization and verify language data exists.
- Run one silent warm-up utterance after initialization.
- Speak cues with `TextToSpeech.QUEUE_FLUSH` so a new cue interrupts stale speech.
- Release the engine with `shutdown()` when its owner is destroyed.
- Preserve onset/resolution haptics from §12.5.
- If Google TTS or en-IN data is unavailable, disable spoken cues and show a setup message. Do not
  silently switch to another engine.

## Tests

- Fake speaker proves cue deduplication and arbitration.
- Fake speaker proves a newer cue uses queue-flush semantics.
- Initialization-state test proves cues are ignored until Google TTS is ready.
- Missing-engine and missing-language tests produce the setup state without crashing.

## Device gate

- Diagnostics confirm `com.google.android.tts` is installed.
- en-IN voice data is available.
- First real cue speaks.
- A newer cue interrupts stale speech.
- Speech still works in airplane mode after voice data is downloaded.
- Fault onset and resolution produce their specified haptics.

## User setup

Before the device gate:

1. Install or update **Speech Recognition & Synthesis** by Google from Google Play.
2. In Android settings, open text-to-speech settings and install the English (India) voice data.
3. Set media volume to an audible level.
4. Connect the phone through USB only when requested for the device gate; disconnect it after the
   gate to save laptop battery.
