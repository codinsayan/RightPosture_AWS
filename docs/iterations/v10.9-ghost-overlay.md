# Version 10.9 — Ghost overlay in the live set

Status: in-progress — implemented and unit tested; device gate not yet run.  
Source: §14.2; new work

Scope: draw the ghost over the camera preview during a patient's set, with a toggle, a count-in
readout and a quiet "you are behind" line. Bilingual, like every other patient-facing string.

Only reachable once 10.5's sign-check gate has passed on a device. That is the whole point of the
ordering.

Tests: the panel shows the count-in while the clock is counting; the behind-the-guide line appears
only past a threshold; both strings exist in English and Hindi.

Device gate: a full patient set with the ghost visible. Check the toggle works mid-set, and check
the frame rate — the pose pipeline shares the GPU and this adds a second skeleton to every frame.

## Result

- `camera/LiveGhost.kt` (Track B, no Android types) - `LiveGhost.update(state, frame, timestampNs,
  imageAspect, liveMirrored, prescribedReps)` runs once per 33 ms UI tick beside the engine:
  10.8's clock, 10.5's placement, 10.6's `forCamera`, 10.7's retargeting against a 90-frame
  rolling median of the patient's limbs (refreshed every 30 frames). Returns `LiveGhostFrame(tick,
  ghost, bones, hint)`.
  - Reads the engine, never writes to it. Patient moving = `phaseState != IDLE`.
  - **Rep completion from the counters** (`validReps + partialReps` rising), not `completedRep`:
    that field lives one engine frame, and a 30 Hz sampler of a 30 Hz engine misses some.
  - Set complete = `validReps >= prescribedReps`, which stops the guide (nothing drawn).
  - `GhostHint`: `CountIn(seconds)`, `Waiting`, `Behind`. Behind uses hysteresis - on past 25
    phase of lag, off below 15 - so a patient at the edge does not make it flicker.
  - `LiveGhost.from(bundle)` is null for a bundle without a skeleton, which is what hides the
    toggle on every pre-10.4 exercise.
- `drawableBones(skeleton, phase)` - per-bone abstention: a bone is drawn only if both ends had
  authoring visibility >= 0.5 and spread <= 0.25 torso lengths at that bin. Generous on spread on
  purpose: the moving wrist reached 0.17 on device, and hiding the taught limb defeats the guide.
- `camera/CameraPreviewScreen.kt` - the guide is drawn **under** the live skeleton, white at 55%
  and 18 px with round caps, gated on `inExercise && startBundle != null && ghostOn`. Above the
  panel, one hint line and a "Guide: on/off" toggle, shown only when the bundle has a skeleton. An
  `RPGhost` line when the set starts (`guide=on` or `none`) and every 2 s during it: guide state,
  guide and patient phase, lag, drawn, bone count, hint, toggle, reps, fps.
- `core/live/Phrases.kt` (Track B carve-out) - `ghostCountIn`, `ghostWaiting`, `ghostBehind`,
  `ghostToggle`, in English and Hindi. Shown, not spoken: speech is for faults and counts, and
  saying "you're behind" aloud every few seconds would be nagging.
- `LiveGhostTest` - 10 cases: count-in shown while counting and gone once moving; behind only past
  the threshold, held between the two, cleared on catching up; a still patient is asked to get
  into position; all four lines in both languages; an engine-counted rep resyncs; a rejected one
  too; the guide stops at the prescription; a clean skeleton draws every bone it carries; a poorly
  seen ankle hides only its own bones; an inconsistently placed wrist is not drawn.

Commands: `gradlew testDebugUnitTest installDebug` - BUILD SUCCESSFUL; 891 tests, 0 failures.

## Traps

- **Gate on `inExercise && startBundle != null`.** `pose` is set during physio recording and during
  calibration too, so a ghost drawn on `pose != null` alone appears in flows where it is leading
  nobody through anything.
- **Only offer the toggle when there is a ghost to hide.** A dead control on every pre-1.2 exercise
  is worse than no control.
- Draw it *under* the live skeleton, translucent and thicker, so it reads as a target to move into
  rather than as a second reading of the patient's own body.
- Per-bone abstention, not all-or-nothing: skip a bone whose stored authoring visibility was low or
  whose spread was large, and draw the trunk anyway. Hiding the whole ghost because one ankle is
  uncertain throws away the part that was fine.
- `CameraPreviewScreen` is already ~1700 lines and holds authoring, calibration, the cyclic set and
  the hold flow. This adds to it. Splitting it is flagged in PARALLEL-TRACKS and is not this
  iteration's job, but do not make it worse than necessary.
